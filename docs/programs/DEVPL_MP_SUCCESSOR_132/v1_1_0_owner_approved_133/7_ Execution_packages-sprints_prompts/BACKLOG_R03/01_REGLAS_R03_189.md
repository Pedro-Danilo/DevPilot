# Reglas R03 para ejecución incremental

1. Aprobación **individual** de sprint y prompt antes de write; ambos permanecen DRAFT hasta la instrucción Owner. Autoridad programática A188 no concede ejecución automática.
2. Preflight: branch, HEAD/commit anterior, Git index/worktree/untracked, Source Registry, `project.yaml`, tres FROZEN, identificador workspace, recibos M2, fragmentos de documentación afectados. No comparar LF/CRLF físico ni prohibir paths ajenos irrelevantes sin riesgo.
3. Operador Windows mínimo y recuperable: archivo Python, modos `verify`, `apply`, `test`, `collect`, `package`; si es necesario dividir API/UI en consolas foreground. No reemplazar artefactos FROZEN ni runtime Project por scripts de operador.
4. Todo rollback, `git reset/clean`, `push --force`, egress/API E, escritura en workspaces o dependencia nueva exige contrato propio y aprobación material; por defecto prohibido.
5. `Quality Gate` proporcional A188: BLOCK únicamente material, REVIEW_REQUIRED si no hay prueba semántica, WARN cosmético. No doble approval para una decisión cubierta por Architecture.
6. Cada sprint incorpora `README/checkpoint` con implementado/probado/pendiente, evidencia ZIP+SHA y `git archive HEAD`. El siguiente sprint usa como baseline el ZIP y HEAD auténticos de Windows.
7. Resultado M3 honesto: `PASS_WITH_FINDINGS` permite hallazgos no críticos, no certifica autonomía profesional ni release listo. Evidencia de segundo dominio para generalización de perfiles.
