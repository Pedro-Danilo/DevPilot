# ADR R01-06/158 — Coverage por proyecto sobre el registro único

**Estado:** propuesta técnica implementada en candidato; publicación documental gobernada pendiente. **Ámbito:** R01-06.

## Contexto
El catálogo de perfiles `ArtifactProfileRegistry` ya gobierna la selección y las secciones. R01-05 añadió aplicabilidad por proyecto. Un validador por mera existencia confundía un archivo o plantilla con calidad aceptada.

## Decisión
Agregar `ArtifactCoverageGate` de solo lectura, invocado por método `ArtifactProfileRegistry.evaluate_coverage`, con reglas explícitas del proyecto y etapa. Ningún catálogo nuevo ni cobertura universal artificial. Separar `REQUIRED`, `CONDITIONAL`, `RECOMMENDED`, `NOT_APPLICABLE`; distinguir `BLOCK`, `WARN`, `REVIEW_REQUIRED`, `NOT_DUE` y `PASS`.

Un PASS exige contenido estructural no vacío y evidencia **externa** de revisión semántica; la clase jamás inventa esa aceptación. Dependencias con frescura desconocida van a revisión. No modifica artefactos ni aprueba publicación. Paths sólo bajo raíz permitida. No se ejecuta código de modelos/API ni se altera la autoridad de `09-C`.

## Consecuencias
Primera vertical programática y acotada; la persistencia de decisiones humanas, revisión semántica automatizada, catálogos profesionales completos, UI y publicación Markdown se gobiernan por incrementos sucesores. Los documentos históricos no se reescriben ni se duplican.
