# ADR — Settings UI persistente con autoridad server-side

**Decisión:** Reutilizar `PersistentSettingsStore` de R01-10; introducir tres rutas HTTP declaradas en API_ROUTE_POLICIES, ServerRBAC y contratos OpenAPI. El cliente usa cookies de sesión/CSRF y solo envía propuesta tipada. El backend valida claves, ámbitos, revisión CAS, Owner y aprobación de escritura; `runtime_modified=false` sin excepción. Mantener proveedor disable/revoke con autoridad separada y sin efecto derivado del ajuste guardado.

**Alternativas rechazadas:** usar legacy API token para escritura; almacenar preferencias en localStorage; activar modelo local/externo por defecto; editar libremente YAML; duplicar store; omitir cambios en catálogos; declarar UX PASS sin navegador.

**Riesgo:** la integración completa (Vite + FastAPI + browser Windows) exige evidencia de ejecución real y capturas antes del push. SSR/gestión de roles/grants siguen perteneciendo a servicios existentes. No se altera memoria histórica ni se autoriza E.
