# ADR R01-07: publicación documental gobernada, separada del visor

**Decisión:** `GovernedMarkdownPublisher` se implementa como servicio independiente de `WorkspaceDocumentsApplicationService` (solo lectura). La ejecución es `False` por defecto; requiere aprobación de contenido, ruta confinada `docs/published/`, tests existentes, fingerprint del Source Registry y lock exclusivo.

**Autoridad:** publicar Markdown y actualizar Source Registry, grafo `documentation_authority_graph.json` y label del overlay conjuntamente. Las validaciones aceptan LF/CRLF textual, no bytes físicos del checkout. Los documentos existentes/FROZEN nunca se sobrescriben. Se conserva historial y unicidad `doc_id`/ruta. Ante fallo transaccional se intenta compensar las escrituras ya hechas y permanece un BLOCK; si se produce un cierre abrupto del proceso, la siguiente inspección debe detectar y bloquear el drift, no autocorregir silenciosamente.

**Alternativas descartadas:** hacer escribible el explorador de documentos (rompe separación de permisos), publicar sin Source Registry (drift), permitir sobrescritura FROZEN (destruye historial), requerir API externa (costo y egress).

**Limitaciones:** no hay nueva UI; la aceptación semántica del documento viene del humano, no de la presencia del frontmatter. No se realiza una publicación real de documentos durante la prueba Windows. Antes de uso industrial multi-proceso, evaluar recuperación post-crash y el proceso de Git commit para publicaciones reales; la exclusión actual evita dos escritores cooperantes, pero no es una transacción de sistema de archivos atómica entre varios ficheros.
