# ADR-R01-10 — Persistencia de configuración gobernada

**Estado:** ACCEPTED_FOR_R01_10_CANDIDATE; **baseline:** `7799546548ecc37b3e7afac40271a26a6931011a`.

## Contexto
`SettingsApplicationService` presenta workspace/providers/policy en read/plan-only. `ExternalProviderEnablementService` posee habilitación/revocación operacional, por lo que no puede existir una segunda autoridad que active red o ejecución mediante la simple edición de configuración.

## Decisión
Añadir `PersistentSettingsStore` (SQLite local, event versions) con claves estrictamente tipadas y scopes plataforma/workspace/proyecto, proyección `effective_value` y `origin`. Autorización Owner mediante principal/sesión humana, `ServerRBACEnforcer` y ámbito workspace; aprobación explícita solo de escritura. Precondición CAS de revisión y rollback agregando una nueva versión. Ninguna clave puede reducir floors DENY. Reutilizar `SettingsApplicationService`/`ApplicationService` como fachada sin crear rutas HTTP en este incremento (exigen catálogo RBAC propio, previsto R01-11).

**Seguridad:** solo claves tipadas públicas, no claves ni valores secretos, no editor YAML, no runtime kill/revoke ni conexión real, no endpoints sin server RBAC. `generation.default_route=local` es preferencia persistida, no autorización de runtime.

**Evidencia:** focal Python sobre reinicio, CAS, plan, rollback, scope, rol, no-egress y secretos rechazados.

**Límites:** integración API/UI browser en R01-11; no declara evaluación de proveedores reales; no se altera Source Registry (puntero de R01-09 vigente, documentos aprobados son externos a git hasta publicación gobernada).
