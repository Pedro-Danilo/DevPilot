# ADR-MP-132-008-S2 — Robustez del preflight y recuperación COR-142

**Estado:** OWNER_REQUESTED / WINDOWS_EXECUTION_GATED. **Naturaleza:** adenda focal a ADR-MP-132-008 y S1-141; no sustituye el baseline histórico ni autoriza R00-03.

## Hallazgo reproducido

COR-141 se detuvo en `inspect` porque la consulta CIM encontró PID `8264`, `python.exe`, con referencia textual a las rutas de DevPilot. La salida no demuestra que fuera un servidor ni que bloquease físicamente archivos. Ninguna mutación Git se ejecutó.

## Decisión focal de COR-142

1. La coincidencia de rutas en `CommandLine` o `ExecutablePath` **no es un gate de bloqueo por sí misma**. Se registran PID, nombre y clasificación, no argumentos o secretos.
2. Se bloquean automáticamente solo firmas identificables de servidores de DevPilot (por ejemplo uvicorn, Vite, API/UI). Cualquier proceso no reconocido queda como `PATH_REFERENCE_ONLY`, requiere valoración manual del Owner y no puede tratarse como garantía de ausencia de locks de Windows.
3. Siguen siendo obligatorios: root Git único, rama/HEAD exactos, tracked/untracked clean, locks básicos ausentes, upstream remoto comprobado, backup Git, dos confirmaciones expresas y smoke tras migración. En `retire`, los locks que impidan borrar producirán BLOCK real sin mayor fuerza ni eliminación alternativa.
4. No comparar recuentos volátiles de ignored para detectar drift entre fases. Sí comprobar identidad Git, ubicaciones, refs y HEAD. El Owner inspeccionará ignored antes de autorizar su eliminación.
5. Una interrupción posterior a un comando Git y anterior al checkpoint se reconciliará por estado Git live **solo en los tres estados exactos** `BEFORE_DETACH`, `MP_DETACHED`, `MAIN_SWITCHED`; cualquier otro estado => BLOCK y análisis manual.
6. Si `worktree remove` terminó pero no se escribió recibo, podrá reconstruirse este recibo únicamente si el worktree está simultáneamente **ausente del registro Git y del disco** y MAIN conserva HEAD y rama correctos. Nunca repetir automáticamente una eliminación parcial.
7. El backup se escribe primero como temporal verificable para evitar un `.bundle` truncado que parezca definitivo.

## Restricciones heredadas conservadas

No source writes, commit, push, merge, `reset --hard`, `--ignore-other-worktrees` ni `worktree prune` masivo. El segundo token es obligatorio para `git worktree remove --force`. Preservar las 63 entradas históricas salvo el worktree MP elegido.

## Límite de seguridad

Una clasificación heurística por comandos no acredita que **todos** los procesos con locks estén detenidos. Ante dudas, cerrar API/UI/terminales desde sus propias consolas y comprobar la información local de PID. El operador no mata procesos. La guía prohíbe ejecutar con servicios DevPilot abiertos.
