# ADR-MP-132-008-S1 — Retirada del worktree MP tras consolidación

- **Tipo:** addendum sucesor a ADR-MP-132-008, externo al source hasta R00-03.
- **Origen de autoridad:** solicitud explícita Owner, 2026-10-14; `R00_02_OWNER_DECISION_140.txt` permanece histórico `PENDING` sin falsificación de cierre A.
- **Estado:** OWNER_REQUESTED / WINDOWS_EXECUTION_GATED (no declarar ejecutado sin recibo).
- **Baseline de entrada:** `evolution/multiprovider-v2@8db5b44694abcced3231183e05731e732f5b8f24`.

## Problema y cambio

ADR-008 y el prompt 134 prohíben **borrar worktrees** durante la migración B. Esa restricción era apropiada para preservar recuperación. El Owner ha resuelto que la ubicación de operación sea exclusivamente `D:\Projects\DevPilot_Local` y que el linked worktree `D:\Projects\DevPilot_Worktrees\DevPilot_Multiprovider` sea **retirado definitivamente**. La eliminación no es una prueba de que se pueda recuperar el contenido ignored del linked worktree.

## Decisión sucesora limitada

1. Inspeccionar ambos worktrees y requerir HEADs exactos, estado clean, lock ausente, servicios detenidos y remoto verificado; sin nuevas tareas R00-03.
2. Crear **Git bundle externo** de ambas ramas y validarlo; conservar `official/devpilot-local` como referencia histórica.
3. Exigir confirmación Owner `MIGRATE_WORKTREE_B_R00_02` y hacer `git switch --detach --no-overwrite-ignore` en MP; luego `git switch --no-overwrite-ignore evolution/multiprovider-v2` en MAIN. Prohibidos `reset --hard`, `--ignore-other-worktrees`, `force push` y segundo root Git.
4. Validar HEAD, rama única checked-out, origen remoto y `devpilot_core` importable desde `.venv` en MAIN.
5. **Solo después de una segunda aceptación explícita** `YES_DISCARD_MP_IGNORED_DATA`, retirar el antiguo linked worktree usando `git worktree remove --force`, nunca dos `--force`. La segunda aceptación reconoce que Git puede destruir ignored del linked worktree. No se alteran los demás worktrees.
6. Si la migración falla antes de retirar MP, conservar estado observado y habilitar recuperación manual gobernada. No hay rollback automático destructivo. El Old MP no se considera desactivado hasta que Git deje de registrarlo y el directorio no exista.

## Trade-off aceptado

Se pierde la disponibilidad local inmediata de ignored/runtime/evidencias alojadas *dentro del directorio MP retirado*. La eliminación no equivale a borrar historial Git: se conserva rama y refs. No se exportan secretos ni datos ignored al ZIP de evidencia; el Owner debe hacer copia separada de cualquier archivo ignored que necesite antes de autorizar `retire`.

## Relación con R00-03

Esta ADR no actualiza el Source Registry, Project State ni Overlay. La primera mutación documental sigue siendo R00-03, tras adjudicar `G-R00-02`; publicar allí elección B, nuevo path único operativo, retiro de linked MP y supersession del antiguo supuesto de preservación de linked MP.
